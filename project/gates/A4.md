# A4 Stage Gate — Experience Engine v1

**Decision:** PASS WITH FOLLOW-UP
**Commit/PR:** implementation evidence through `316497cb5c7a9e2826dd0dde899b340312b59f31`; phase closure from A4-P
**Date:** 2026-09-10

## Acceptance
- A4 promised a framework-independent authored experience engine with deterministic step graphs, assessments, retries, hints, checkpoints/resume, tool permissions, typed state/events, and content validation.
- The delivered engine owns educational authority in pure TypeScript, exposes one guarded command mutation path, validates authored definitions before execution, authorizes bounded tool intents without executing provider/world work, and restores only semantically valid checkpoints.
- A4-Q found four blocking authority/recovery issues; A4-F resolved all four with adversarial regression coverage before this gate was recorded.

- Unit/integration: the same run passed the complete deterministic test suite, including stale/replayed command rejection, authored-definition mutation isolation, semantic checkpoint reconstruction, finite numeric tool parameters, assessment/retry/hint behavior, restart, and resumed-vs-uninterrupted equivalence.
- Browser/e2e: main CI `34490166471` passed the existing browser stage-gate after A4-F bookkeeping. A4 itself changed no React/Phaser/rendering/navigation/audio surface.

## Critique
- Architecture: PASS. Experience/curriculum authority remains in pure TypeScript, with renderer/provider/backend/native code excluded. The final public mutation boundary requires step/revision authority and tool requests remain bounded intents.
- Product/learning: PASS. Correctness, retries, hints, mastery-relevant transitions, completion, and resume behavior are deterministic rather than tutor/model-owned.
- UX/visual: NOT MATERIALLY CHANGED. No new rendering surface was introduced.
- Resilience: PASS. Restart, JSON checkpoint round-trip, semantic resume verification, stale/duplicate requests, malformed policy, and impossible/fabricated checkpoint paths fail closed.
- Performance: PASS FOR CURRENT SCOPE. A4 adds pure-TypeScript state/validation machinery only; representative large-content profiling should happen when A6/A15 provide realistic authored density.
- Safety/privacy: PASS. AI/provider code cannot change curriculum truth directly; declared tool authorization is deterministic and no new personal data or network dependency was added.

## Findings
### Blocking
- None. All four A4-Q blockers were resolved in A4-F and covered by focused deterministic evidence.

### Non-blocking follow-ups
- Measure validation/runtime cost against representative authored graph/content density when A6/A15 provide realistic content rather than inventing a synthetic A4 performance target.
- A5 must consume the guarded A4 command/tool authority APIs rather than recreating educational truth inside tutor/provider orchestration.
- A11 persistence must continue treating checkpoint payloads as untrusted input and preserve semantic validation before restoration.

## Decision rationale
A4 now provides the deterministic authority boundary that A5 needs: tutor/model orchestration can observe state, request bounded commands/tools, and narrate behavior without owning assessment, progression, or checkpoint truth. The QA blockers were fixed before closure, focused implementation CI is green, and no A4-specific visual/device regression exists. The remaining follow-ups are deliberately tied to later representative content and persistence work and do not undermine A5, so it is safe to begin Tutor/AI orchestration v1.
